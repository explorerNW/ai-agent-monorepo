# `env.ts` 技术文档

## 📖 文件概述

`env.ts` 是项目中的**环境配置中枢模块**。基于提取的接口与函数结构推断，该文件主要负责：

- 定义环境变量的 TypeScript 类型契约，消除 `process.env` 的 `any` 类型污染。
- 提供安全、可预测的环境变量读取方法，内置默认值、格式校验与降级策略。
- 作为前后端分离架构或微服务架构中，配置管理的单一事实来源（Single Source of Truth）。

该文件通常与 `dotenv`、`zod` 或自定义配置校验器配合使用，确保应用在开发、测试、预发、生产等不同环境中行为一致。

## 💡 典型使用示例（推断）

```typescript
// 1. 配置加载与类型约束
import { EnvConfig } from "./env";

const config: EnvConfig = {
  NODE_ENV: process.env.NODE_ENV || "development",
  API_BASE_URL: process.env.API_BASE_URL,
  PORT: process.env.PORT || "3000",
  // ...
};

// 2. 安全获取 API 地址
import { getApiUrl } from "./env";

const baseUrl = getApiUrl(); // 返回标准化字符串
fetch(`${baseUrl}/users`, {
  /* ... */
});
```

## ⚠️ 架构师建议与注意事项

1. **运行时校验不可省略**：TypeScript 类型仅在编译期生效。建议在模块顶层使用 `zod` 或自定义校验函数对 `EnvConfig` 进行运行时断言，缺失关键字段时应直接 `process.exit(1)`。
2. **敏感信息隔离**：`env.ts` 不应硬编码密钥。密码、Token 等应通过 CI/CD 注入或密钥管理服务（KMS/Vault）获取。
3. **避免循环依赖**：该文件应保持零依赖或仅依赖基础标准库，防止被业务模块反向引用导致启动死锁。
4. **多环境构建优化**：在 Webpack/Vite 构建时，建议将 `getApiUrl` 的返回值通过 `DefinePlugin` 或 `import.meta.env` 静态替换，减少运行时开销。
